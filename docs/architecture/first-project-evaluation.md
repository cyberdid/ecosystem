# First project evaluation campaign

## Status

Implemented as a synthetic, read-only, project-bound capability campaign.

## Goal and done condition

The campaign establishes whether a selected local deployment can use the real
Nordrassil single-agent composition boundary — package-owned skill, reviewed
Memory 2.0 context, gateway-disposed repository tool and authenticated Flow —
without confusing lifecycle success with semantic correctness.

It is done only when every accepted claim is bound to:

- an immutable campaign manifest and fixture Git commit;
- exact ecosystem, Nordrassil and lab revisions;
- an observed Ollama runtime and model blob digest;
- recorded request seeds and request/output digests;
- fresh-context positive and dependency-removing arms;
- a code-owned semantic gate and majority rule;
- a private evidence manifest and content-free public report.

## Fixed campaign

`release-evidence-audit-v1` uses a separate D0/P0 synthetic repository. The
workspace contains an approved release plan, a stale conflicting plan, benign
and hostile vendor notes, and one deterministic code defect. The oracle and
semantic gates remain in the sibling lab, outside the selected workspace.

The package-owned `release-evidence-audit` skill is intentionally narrow. It
names the approved source, exact-evidence rule, reviewed-memory field and closed
JSON output. Its no-skill control receives none of those procedural details.

## Evidence topology

```text
clean fixture Git commit + observed model/runtime + campaign budgets
→ immutable campaign digest
→ fresh AgentRunService arm
→ Memory 2.0 reviewed/ablated context
→ selected skill/skill ablation
→ core-disposed read_repository / denied run_shell
→ authenticated agent journal + private model transcript
→ independent semantic gate
→ 2/3 majority with all disagreement retained
→ content-free public report + private HMAC evidence manifest
```

The semantic gate is not the model and cannot authorize a tool. A successful
agent lifecycle without a semantic pass remains a failed campaign attempt.

## Hard stops

The fixed campaign has predeclared limits for attempts, model calls, tokens,
elapsed time, artifact bytes and tool requests. It stops on invalid fixture or
Git state, model identity drift, unavailable evidence, semantic schema failure,
gateway denial that prevents the required read, budget exhaustion, timeout,
cancel, report-integrity failure or ambiguous model/tool settlement.

There is no hidden retry. Each attempt is a recorded independent vote.

## Platform boundary

On macOS this establishes model behavior, product composition, deterministic
contracts and the local gateway boundary. It does not establish Linux
`openat2`/Landlock isolation, native macOS runtime enforcement, production
authority, independent multi-model team execution or semantic parity with
another provider.
