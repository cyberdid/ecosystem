## 1. Спостереження власника (підтверджене)

«Це все політики — і нічого про loop, harness чи подібні речі для функціоналу?» — так. **~85% з 50 тис. рядків — це authority/policy/audit/trust-інфраструктура навколо дій, а не самі дії.**

Це не випадковість, а статут: `.ai/instructions.yaml` визначає мету проєкту як «contracts, policy boundaries, provenance, evaluations», а правило SCOPE-CONTROL прямо каже: *build only stable contracts and enforcement boundaries; adopt mature external runtimes*. Проєкт свідомо будує конституцію, поліцію і нотаріат, а «руки й мозок» (агенти, моделі, скіли) мають приходити ззовні.

## 3. Мапа на оригінальну конституцію (main, Phase 0)

Задум власника: екосистема = **знання + скіли + петлі + ролі моделей**, що переживають зміну будь-якого вендора. Стан фаз:

| Фаза конституції | Що мала дати | Стан |
|---|---|---|
| Phase 0 — хаб | конституція, карта, каркаси | ✅ (2026-07-14) |
| Phase 1 — модельний шлюз, ролі `eco-*` | один endpoint, аліаси за роллю, fallback-ланцюги | 🔴 не почато |
| Phase 2 — канонічні скіли + синк у харнеси | скіл пишеться раз, потрапляє всюди | 🔴 не почато |
| Phase 3 — hub-wiki + STATE.md | пам'ять і знання | 🟡 wiki жива; STATE.md-контракт зник |
| Phase 4 — loops | реєстр працюючих петель | 🟡 контракт і 1 заблокований loop |
| Phase 5 — Hermes-оркестрація | зовнішній агент-оркестратор | 🔴 не почато |

Натомість збудовано те, чого у Phase-плані взагалі не було: M2/M3 enforcement, M4.5 дистрибуція, M4.6 conformance, M5 team authority. Codex три доби будував ідеальну систему дозволів для дій, яких ще ніхто не виконує: **сейф є, поліція є, суд є — магазин не відкрився.**

## 4. Чому це все-таки не марно

Логіка «спершу межі» має сенс: функціонал уже дають Claude Code / Codex / Copilot; ecosystem робить їх взаємозамінними і підконтрольними. Приклад цінності: скіл або MCP-сервер, що потрапить у екосистему, не зможе сам собі видати права — це реальний захист від prompt injection і supply-chain у майбутньому. Але шар керування має цінність лише тоді, коли ним хтось керований користується — а до цього не дійшло.

## 5. План функціонального розвороту (рекомендація)

Пріоритет за принципом «найкоротший шлях до щоденної користі», нові мілстоуни — заморозити.

### Крок 1. Розблокувати єдиний loop (≈1 день на WSL)
Заскриптувати церемонію ключів (команда типу `eco runtime trust init` або операторський скрипт поза рантаймом — сумісно з ADR-019) → виконати на WSL → перший справжній `PASS` `wiki-health-check` → ненульовий exit-код при `blocked` у `eco run` (зараз 0 — пастка для cron).

### Крок 2. Phase 2 конституції: скіли (≈1–2 дні, найбільша щоденна віддача)
- формат уже визначений конституцією: `skills/<name>/SKILL.md` з frontmatter `name`, `description`;
- перші кандидати: (а) скіл «working with ecosystem contracts» — як правильно міняти `.ai/` і ганяти гейти; (б) скіл «loop authoring» — 4 артефакти + hard stop; (в) перенесення 1–2 реально використовуваних промптів власника;
- синк: спершу тривіальний скрипт (symlink/copy у `~/.claude/skills`, `~/.codex/skills`), потім за бажанням як `eco skills sync` з тими ж ownership-маркерами, що в M1-проєкціях. M1-компілятор уже вміє все потрібне (детермінізм, дрифт, uninstall).

### Крок 3. Phase 1: ролі моделей (≈1 день)
Не піднімати LiteLLM заради LiteLLM: почати з `.ai/deployments.yaml` — додати ролі `eco-orchestrator`/`eco-worker`/`eco-grader` як логічні аліаси над уже наявними адаптерами (Ollama + Claude). Fallback-ланцюги — лише в конфігу шлюзу, коли шлюз реально з'явиться.

### Крок 4. Перший loop з моделлю через M3 (≈2–3 дні)
`wiki-health-fix`: той самий D0-скоуп, але модель *пропонує* виправлення, а застосування йде через повний M3-ланцюг (proposal → policy → людський підпис → CAS-запис → rollback). Це перше з'єднання «поліції» з «роботою» і справжній зміст M4-промоушну L3.

### Крок 5. Повернути пам'ять (≈0.5 дня)
STATE.md за 5-секційною конвенцією конституції як «людська проєкція» + правило в `.ai/instructions.yaml`, що сесія завершується записом. Без цього уроки сесій і далі випаровуються.

### Процесні правила на час розвороту
1. Жодних нових M-рівнів, поки кроки 1–4 не зелені.
2. Кожен «Complete» — лише з зовнішнім рев'ю (людина або незалежний агент), не самоатестацією.
3. Мірило прогресу — не рядки і не звіти, а **кількість днів, коли екосистема реально щось зробила для власника**.
