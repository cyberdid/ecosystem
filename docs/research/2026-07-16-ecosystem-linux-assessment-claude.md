## 1. Що це за проєкт

Особиста **платформа довіри для AI-агентів**: контракти, компілятор інструкцій і рантайм, у якому агент нічого не може сам — кожне читання, запис, виклик моделі проходить через policy-рішення, підписані докази й журнал із криптографічним ланцюгом. Не «обгортка над LLM», а спроба збудувати policy enforcement point для агентів із доказовістю замість довіри — те, що зазвичай мають лише регульовані компанії.

Траєкторія: за 3 доби агент Codex збудував 50 тис. рядків (M1→M5.7); після зовнішньої рецензії (ранок 2026-07-16) за один день закрив більшість зауважень і надбудував M4/M5. Темп ~20 тис. рядків/добу зі стабільною якістю.

## 4. Безпекова постава (модель загроз Linux)

**Захищає від:** агент без креденшелів/мережі (namespaces+Landlock), path escape і symlink/hardlink-раси (openat2), replay/substitution (одноразові nonce-рішення, 14-дайджестні approval-суб'єкти), часткові записи (CAS+recovery), витік контенту в журнал (лише дайджести, keyed path refs).

**Не захищає від (і чесно каже):** атакер на тій самій машині з ключами (embedded-профіль — симетричний HMAC; M5 вже Ed25519, M3-approval поки HMAC), відсікання хвоста журналу без зовнішнього якоря, компрометація процесу. Задокументовано в ADR-013/017/019/025.

Найбільша практична прогалина — не криптографія, а те, що enforcement ще ні разу не стояв на шляху реального агента.

## 5. Ризики процесу

1. **Борг розуміння.** 50 тис. рядків щільного захисного коду за 3 доби; тести — єдиний реальний контракт супроводу. Поки гейт зелений, наступний агент може безпечно міняти код; людина сама — навряд.
2. **Самоатестація.** Кожен «Complete» написаний автором коду в той самий день. Пом'якшено зовнішньою рецензією і Copilot-рев'ю на PR, але патерн лишився.
3. **Ширина замість глибини.** Рекомендацію «один живий loop» виконано наполовину: loop збудували — і пішли будувати M5. Платформа готова на ~90%, використання — на 0%.
4. **Bus-factor навпаки:** підтримувати проєкт може лише агент такого ж класу; зелений CI-гейт стає священним.

## 6. Вердикт

Найякісніший агентський проєкт із рецензованих: верхній відсоток за інженерною дисципліною і — рідкісніше — за чесністю заяв. Як Linux-платформа для майбутніх керованих агентів фундамент справжній: тести, негативні кейси, crash-recovery, live-докази.

Але сьогодні це **інститут стандартизації без жодного клієнта**: збудовано сейф, сертифіковано сейф, написано 25 стандартів про сейф — і ще жодна річ у ньому не полежала. Дистанція до реальної цінності — один спринт: церемонія ключів → перший PASS `wiki-health-check` на WSL → перший корисний звіт.

**Інтегрально: 7.5/10** (інженерія 8.5, чесність 9, тести 8, пріоритети 5, практична цінність сьогодні 3). Потенціал 9+, якщо наступний тиждень буде про використання, а не про M6.

**Наступні кроки:** (1) змержити PR #2; (2) заморозити нові мілстоуни; (3) unlock-спринт: церемонія ключів як команда/скрипт, перший live PASS, ненульовий exit при `blocked`; (4) хвости: підключити зовнішній anchor, прибрати мертвий re-lease код.

## Додаток. M1→M5.7 простими словами: що кожен шар реально виконує

Метафора: проєкт будує «держслужбу» для AI-агентів — правила, паспорти, охорону, нотаріуса й архів.

**M1 — єдині правила для всіх асистентів** 🟢 *працює щодня.* Інструкції живуть в одній теці `.ai/` (5 yaml); файли для Codex/Claude/Copilot/Gemini/Cursor генеруються з канону, як PDF з Word. `eco validate` (несуперечність, без секретів), `eco render` (+`--check` ловить ручні правки), `eco doctor`, `eco uninstall`.

**M2 — охоронець і архіваріус для читання** 🟢 *працює в тестах (Linux).* Агент не читає сам: запит → PolicyEngine (default deny) звіряє з незмінним планом → одноразовий дозвіл (квиток) → брокер читає так, що не обдуриш symlink-ом → усе в SQLite-журнал із зчепленими записами. Агентський процес — у клітці (namespaces+Landlock, без мережі і ключів). Два адаптери моделей (Ollama, Claude) з підписаним live-доказом.

**M3 — право на один запис під підпис** 🟢 *працює в тестах (Linux).* Як банківська каса: пропозиція з точним «до/після» → policy allow → людина підписує саме цю пропозицію (підпис прив'язаний до кожного байта) → резервна копія і план відкату → атомарна підміна → перевірка → відкат при розбіжності. Виживає вимкнення світла посеред операції.

**M3.5 — зшивка і чесність** 🟢 *зроблено.* CLI й рантайм з'єднані: `eco runtime doctor` чесно каже, що готове, а що заблоковане. pytest ставиться (`.[test]`), CI чесно розмічає скіпи, ADR-018 формально примирив нову архітектуру з Phase-0 конституцією.

**M3.6 — перевірка довіри без самообману** 🟡 *працює, чекає церемонії.* Система вміє перевіряти довірчі матеріали, але відмовляється сама собі їх видавати. `eco runtime trust doctor` зараз: «ключа немає — заблоковано». Це головний замок на всій системі.

**M4 — перший робот: перевірка wiki** 🟡 *зібраний, заблокований на ключах.* `eco run wiki-health-check`: перевірка wiki без моделі, мережі й записів; кар'єрні правила — підвищення L0→L2 лише після 5 успішних відтворюваних прогонів, рівні з правом зміни (L3+) структурно неможливі.

**M4.5 — валізка для переїзду** 🟢 *працює на 3 ОС.* `eco adopt` (акуратно всиновити інший репозиторій, з превʼю і квитанцією), `eco platform` (пасивна довідка можливостей платформи), `eco distribution` (офлайн-пакет із маніфестом; CI збирає і смоук-тестить, 0.7.0).

**M4.6 — іспит для машини** 🟢 *працює (Linux).* `eco conformance` активно перевіряє namespaces/Landlock конкретної машини і записує спостереження-доказ; спостереження ≠ права.

**M5 — паспортний стіл і колективні правила** 🟢 *працює, «на виріст».* Ed25519-особи, підписані deny-all політики (`eco identity`, `eco policy`), RBAC/ABAC що лише звужує, спільний журнал активацій, відкликання, аварійне відновлення, ротація, кворум різних людей із розділенням обов'язків, `eco team`, реліз 0.7.0. Команда поки з однієї людини.

**Вузьке місце всієї системи:** церемонія ключів (M3.6). Після неї M4-loop робить перший справжній прогін — і платформа переходить зі стану «збудовано й сертифіковано» у «працює».
