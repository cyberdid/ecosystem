# M3.6 verification-only trust bootstrap report

**Date:** 2026-07-16
**Status:** complete for the M3.6 verification-only boundary; local gates and [GitHub Actions run 29479427435](https://github.com/Pylypko1021/ecosystem/actions/runs/29479427435) passed.

## Purpose

M3.5 proved that the installed CLI can construct the embedded runtime, but it correctly refused execution without external trust inputs. M3.6 adds a canonical, verification-only bridge for those inputs. It does not turn runtime doctor keys, Git files, or a model request into authorization.

## Delivered contract

`.ai/trust.yaml` is a canonical `RuntimeTrustBootstrap` policy. It declares only bounded metadata:

- the `local-shared-key` HMAC compatibility profile and allowed issuer/key identifiers;
- strict `env:ECO_*_EVIDENCE_KEY` references for verification material;
- strict `env:ECO_*_ENVELOPE_FILE` references for externally managed snapshot and conformance envelopes;
- an exact D0, read-only wiki/document snapshot scope; and
- exact trusted suite/deployment observation bindings when a future model-routed workflow needs them.

There is no signing key, signed envelope body, provider credential, endpoint, prompt, response, or model identity secret in Git. `eco runtime trust doctor --json` resolves only the references declared in that canonical policy, verifies canonical envelope bytes, issuer/key/kind, project, current repository root identity, exact entry scope, deployment identity, suite, freshness, and expiry. Its JSON exposes only safe status codes and counts.

Evidence files must be absolute, externally located, regular, non-symlinked, private files. Repository-resident, world/group-readable, hard-linked, malformed, missing, or changed evidence fails closed. The doctor creates no SQLite state, artifact store, broker, run, model request, network egress, write authority, or repository read.

## Trust boundary

The embedded HMAC profile is explicitly **local-shared-key**. A separate operator-controlled signing ceremony must prepare the evidence; the executable runtime never invokes `HmacEvidenceSigner` or accepts a raw signing key. This authenticates a configured shared boundary only. It is not third-party non-repudiation, a provider attestation, immutable-model provenance, or compromise separation between signer and verifier that share the same key.

An absent local key or evidence file is the expected baseline result: `ECO_RUNTIME_TRUST_KEY_UNAVAILABLE` or a similarly typed deny. It must never be replaced by ephemeral self-signed evidence.

## Evidence and tests

The gate covers positive externally signed fixtures plus negative cases for literal keys, malformed/noncanonical evidence, unknown issuer/key, changed root/scope, missing key, insecure permissions, symlinks, repository-resident evidence, and required conformance envelope bindings. Diagnostics are tested not to echo secret markers, filesystem paths, Markdown content, or exception text.

## Deliberate non-claim and next gate

M3.6 does **not** run `wiki-health-check`. The existing `RunPlan` contract is model-routed and starts an adapter lifecycle; using it for a no-model deterministic inspection would falsify the audit record. The next M4 implementation slice is a separately versioned **no-model A1 plan and lifecycle contract**. It must consume this verified bootstrap, authorise a fixed `wiki-health-check` scope, execute reads only through the existing policy/store/broker path, emit a content-free report, and remain incapable of model egress or writes.
