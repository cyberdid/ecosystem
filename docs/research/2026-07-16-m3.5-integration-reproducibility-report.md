# M3.5 integration and reproducibility report

**Date:** 2026-07-16
**Status:** implemented locally; remote GitHub Actions evidence is recorded after the branch is pushed.

## Purpose

M3 and its tests proved bounded read/write primitives, but the independent review correctly found two adoption gaps: the installed `eco` CLI did not compose the runtime, and a clean GitHub runner could not reproduce the stated test gate. M3.5 closes those gaps without broadening runtime authority, enabling a model, or authorizing a workspace write.

## Findings addressed

1. GitHub-hosted Ubuntu can execute the deterministic contracts, but its container policy can deny the user/net/pid namespace and Landlock controls required for the live isolation profile. Treating that as a normal test error made CI red; treating it as a passed sandbox would be false.
2. The repository documented a pytest gate but did not declare pytest as an installable dependency.
3. M2/M3 components could be imported by tests and scripts, but no installed CLI command constructed the complete embedded runtime boundary.
4. The Phase-0 human constitution had been replaced by generated projections without a dated supersession decision.

## Delivered boundary

`eco runtime doctor --json` is a non-executing composition probe. It constructs and verifies a real `PolicyEngine`, private ephemeral `SQLiteRuntimeStore`, `ContentAddressedArtifactStore`, Linux descriptor-anchored repository snapshot, `RepositoryReadBroker`, and `EmbeddedOrchestrator`. It uses freshly generated in-memory keys, makes no model/network request, creates no write authority, and leaves the governed repository unchanged. Its structured output excludes paths and exception messages.

The command deliberately reports `executionReady: false` and `ECO_RUNTIME_TRUST_BOOTSTRAP_REQUIRED`. A real repository read requires a configured enabled deployment, signed conformance observation, signed repository snapshot, and production trust-key provisioning. Those inputs are not present in the example canonical configuration. Inventing them only to make `wiki-health-check` run would make a fail-closed boundary performative, so that workflow remains the next explicitly gated integration slice.

## Reproducible test profiles

The `test` extra makes `pytest` a declared, lock-filed clean-install dependency. Hosted CI installs `.[test]` and runs both the authoritative `unittest` suite and pytest discovery, then validates canonical configuration, projection drift, and CLI health.

The live namespace/Landlock tests are capability-conformance tests, not portable unit tests. They run on a capable Linux/WSL host and are explicitly skipped when that kernel profile is unavailable. The ordinary unit tests continue to require fail-closed errors for unavailable isolation, rejected credential bindings, endpoint allowlists, and executable bypass. A skipped live test therefore means **not performed**, never “sandbox passed”. GitHub Actions publishes this scope in its job summary.

## Governance reconciliation

ADR-018 makes `.ai/instructions.yaml` the explicit successor to the Phase-0 `AGENTS.md` constitution while retaining the older document in Git history. It preserves the durable ideas—contracts over vendors, verification before capability claims, verified state, and bounded loops—while removing host-specific LiteLLM/DGX assumptions and the ambiguous dual `L0–L4` terminology. `E0–E4` names the ecosystem stack; `L0–L5` is reserved for loop maturity. Generated client projections are verified against the canonical source.

## Local gate

```bash
python -m pip install -e ".[test]"
python -m unittest discover -s tests -v
python -m pytest
eco validate
eco render --check
eco doctor
eco runtime doctor --json
```

For live isolation conformance, run the same suite on a Linux/WSL host where `LinuxNamespaceLauncher` preflight succeeds. The check proves only the documented Linux/WSL profile; it does not establish a Windows or macOS isolation/write backend.

## Explicit non-claims and next gate

- A green hosted CI result does not prove privileged namespace/Landlock isolation; it proves deterministic contracts and accurate fail-closed behavior on that runner.
- `runtime doctor` proves composition availability, not an authorized execution. It cannot read the repository through a real policy plan, invoke a model, or write files.
- M3 remains a Linux/WSL one-file controlled-write profile. Windows/macOS backends require their own threat model and conformance evidence.
- The next integration gate is production trust bootstrap followed by a deterministic, read-only `wiki-health-check` run that uses a signed snapshot and deployment evidence. Only then may M4 measure repeated loop quality, cost, safety, and recovery.
