# M4.5.1 adoption-bootstrap completion report

**Date:** 2026-07-16

**Scope:** universal, model-neutral filesystem adoption of the ecosystem harness into existing repositories

## Executive result

M4.5.1 adds a safe first installation boundary: `eco adopt --dry-run` creates a deterministic, raw-content-free plan and `eco adopt --apply PLAN_SHA256` applies only the exact recomputed plan. The plan still exposes repository-relative path names and digests, so it is content-minimized rather than information-free. Fresh repositories, valid pre-existing `.ai` contracts, and clean reinstalls have distinct ownership behavior. Existing instruction files are preserved, an adoption receipt makes removal evidence-based, and unsafe or ambiguous state fails closed.

This is deliberately an adoption bootstrap, not a claim that the complete M2–M4 runtime security backend is portable. Linux/WSL remains the only implemented broker/isolation/controlled-write runtime profile.

## Research and review method

The implementation used separate specialist passes:

1. a contract agent defined plan/receipt schemas, lifecycle modes, ownership semantics, and stale-preview behavior;
2. a fixture agent built byte-exact Python and TypeScript-monorepo before-images with CRLF/no-final-newline cases and adversarial filesystem tests;
3. a safety reviewer audited path topology, rollback, uninstall preflight, secret minimization, and concurrency behavior;
4. the primary integration pass reconciled CLI output, projection compiler behavior, portability CI, documentation, regression gates, and Git evidence.

The design was evaluated against the project’s existing contracts-first, preserve-user-work, no-secret, reversible-change, and capability-by-conformance rules. The research question was not “can files be copied?” but “what evidence is sufficient for the harness to know which bytes it owns and can safely remove?”

## Threat model

### Protected assets

- pre-existing repository bytes and directory structure;
- canonical `.ai` contracts;
- client-specific instruction surfaces;
- secret-like values and absolute local paths;
- the fidelity of preview/apply and install/uninstall claims;
- Git history and uncommitted user changes.

### Considered failures and attacks

- a repository changes after preview;
- `.ai` already exists and is silently claimed;
- unmanaged instruction text is overwritten or newline-normalized;
- a projection escapes the repository or resolves through a symlink;
- one file is hard-linked to an external peer;
- a projection is binary/non-UTF-8;
- a crash occurs after some canonical files, projections, or backups are written;
- two cooperating adoption processes apply concurrently;
- receipt, render state, backup, canonical config, or managed projection drifts;
- an unknown file appears below `.ai` before full uninstall;
- uninstall removes pre-existing config or recursively deletes an ambiguous tree;
- audit output reveals a secret value or absolute path;
- a no-op reinstall rewrites files or mtimes.

### Explicitly outside this proof

- a privileged adversary swapping parent directories between validation and the kernel rename;
- complete Windows reparse-point and case-insensitive collision security;
- network, process, package-manager, or provider-account compromise;
- portability of the M2 read broker, M3 write broker, or M4 loop executor;
- authentication/approval of the person supplying a plan digest.
- an attacker that can coherently rewrite the receipt, render state, backups, and repository targets; these are strict local metadata, not signed team identity.

## Contract outcome

Two new JSON Schema 2020-12 contracts are packaged with the CLI:

- `ProjectAdoptionPlan` — preview, modes, counts, relative paths, typed operations, before/after digests, warnings/blockers, and canonical body digest;
- `ProjectAdoptionReceipt` — project/config identity plus exact canonical, projection, and generated-file ownership.

Generated plans are schema-validated, require unique operation paths, and self-verify their `planDigest`. Receipts are schema- and semantics-validated: role, ownership, created digest, and managed-block digest combinations must agree.

Discovery is descriptive only. Detected language/build names may initialize metadata, but no package script or repository command is inferred and executed. Potential secret findings are counted; values are never copied into the plan.

## Implementation outcome

### Preview and apply

- `eco adopt --dry-run [--json]` is zero-write and returns the full sanitized plan.
- `eco adopt --apply DIGEST [--json]` locks the repository, recomputes the plan, rejects stale or blocked state, and applies only that digest.
- A clean reinstall produces no writes and preserves bytes and mtimes.
- Fresh config is built and validated in memory before mutation.

### Projection preservation

The projection compiler now reads existing files as bytes, decodes UTF-8 explicitly, and retains the exact before-image. Backups use byte digests, not newline-normalized text. Apply preflights every projection before any projection write, and uninstall preflights every projected surface before any cleanup.

### Failure rollback

Apply snapshots every planned canonical/generated/projection file and every before-image backup it may create. On an exception, it restores existing bytes and modes, removes newly created files, and prunes only newly empty directories. This provides transactional best-effort behavior for the bounded file set; it is not a general filesystem transaction.

### Safe removal

`eco uninstall --remove-config --yes` now requires a valid receipt and runs a full read-only removal preflight before touching projections. It blocks on drift, unknown `.ai` entries, pre-existing canonical config, unsafe state, or missing evidence. It removes an enumerated owned set and empty parents only; recursive tree deletion is gone.

## Important corrections made during adversarial review

- Text-normalized backups were replaced with byte-exact backups, preserving CRLF and missing-final-newline before-images.
- Reinstall stopped rewriting projection state when nothing changed, preserving mtimes.
- Projection uninstall became full-preflight rather than mutate-while-discovering.
- Full config removal became receipt-enumerated rather than `rmtree(.ai)`.
- The blocked JSON envelope gained a stable top-level error code; successful apply exposes a minimal exact envelope.
- Adoption-created backup files were added to rollback snapshots so an injected mid-apply failure cannot leave private residue.
- Generated plans are validated by their packaged schema and digest before exposure.
- An external per-repository lock rejects a concurrent cooperating apply as `ECO_ADOPTION_BUSY`.
- State-directory and temporary-lock aliases are rejected before read/write; backup authority binds path, full digest, size, and ownership mode.
- Projection/config uninstall uses a second complete preflight plus per-target compare checks so concurrent user bytes are preserved rather than overwritten.
- Every adoption JSON failure is a single sanitized envelope, including invalid generated plans and unexpected late I/O errors.
- Hosted Windows/macOS adoption jobs were separated from Linux runtime-security claims.

## Evaluation corpus

The fixture matrix includes:

| Fixture | Important properties |
|---|---|
| Minimal Python | existing `AGENTS.md` without final newline, Python metadata, tracked secret-reference placeholder |
| TypeScript monorepo | existing CRLF `CLAUDE.md`, nested workspace/build metadata, multiple client surfaces |
| Adversarial topology | stale plan, path escape, symlink, hardlink, non-UTF-8 target, drift, unknown config entry, lock contention, injected apply failure |

Assertions cover exact tree bytes, no-op mtimes, JSON contract shape, absence of absolute paths/placeholder values, zero mutation on blockers, exact restoration, ownership-aware removal, and schema validity.

## Exit criteria

1. Preview is deterministic, content-minimized, and zero-write.
2. Apply requires the exact recomputed plan under serialization.
3. Fresh, existing-config, and reinstall ownership modes are explicit.
4. Existing instruction bytes are restorable exactly.
5. Path aliases, stale state, non-UTF-8, and unsafe ownership fail closed.
6. An injected partial failure restores the bounded original tree.
7. Full removal has a complete zero-mutation preflight and never claims pre-existing config.
8. Focused Linux/macOS/Windows bootstrap tests and the complete Linux regression gate pass.
9. Architecture, ADR, README, research register, roadmap, and `llm-wiki` record the exact proof and non-claims.

## Next plan

M4.5.2 is platform and adapter description, not more implicit detection:

1. define `PlatformProfile` and `AdapterCapabilityProfile` schemas;
2. separate declared, detected, and conformance-proven capabilities;
3. implement read-only `eco platform doctor --json` probes with sanitized evidence;
4. add native Windows, macOS, Linux, WSL, container, and hosted-CI fixtures;
5. keep unsupported broker/isolation/write capabilities unavailable;
6. only then add packaging/install adapters and a portable bootstrap distribution gate in M4.5.3.

M5 team identity/RBAC remains after adoption and platform conformance; filesystem portability must not silently broaden runtime authority.
